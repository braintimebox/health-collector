# 11 — Migration roadmap

Формат: проблема → причина → решение → файлы → риск → проверка → приёмка. Порядок жёсткий: P0 до P1.

## P0 — падение и потеря данных

| # | Проблема | Решение | Файлы | Риск | Приёмка |
|---|---|---|---|---|---|
| P0-1 | падение Settings не локализовано | получить `.ips`, воспроизвести в симуляторе на каждом из 6 подэкранов | `scripts/`, CI | низкий | причина названа, есть регрессионный UI-тест |
| P0-2 | три подэкрана рендерили пустоту | **сделано** (`852e6e1`) | `SettingsTab.swift` | нет | снимки всех шести |
| P0-3 | мусорный URL уводит данные на production | запретить fallback, валидировать схему/хост, не синхронизировать без адреса | `Runtime.swift:43`, `AppSettings.swift:13` | средний: ломает «работало по умолчанию» | тест: неверный URL → ошибка, запросов нет |
| P0-4 | ошибка Keychain не видна | `Result` из записи, текст ошибки в UI | `AppSettings.swift:33-34`, `ServerView` | низкий | тест на отказ Keychain |

## P1 — корректность Runtime и Settings

| # | Проблема | Решение | Файлы | Приёмка |
|---|---|---|---|---|
| P1-1 | тумблер автоматического сбора фиктивен | читать `automationEnabled` в `start()` и перед запуском observer/синхронизации | `Runtime.swift`, `AppSettings.swift` | тумблер выключен → фоновые запуски не читают HealthKit |
| P1-2 | статус фона не наблюдаем | сохранять результат `enableBackgroundDelivery` в состояние, показывать в Advanced | `HealthKitSource.swift:115`, `Runtime.swift` | Advanced показывает enabled/denied/unknown |
| P1-3 | снапшот обновляется только вручную | обновлять по событию + таймер 30 с при активном экране | `Runtime.swift` | рост очереди виден без нажатия |

## P2 — архитектурный рефакторинг

`AppState` + `Config` (валидация) + async HealthKit-адаптер + единая `ErrorModel` + один sync за раз.
Форматы Outbox/Anchors/Wire **не меняются**. Риск: средний (перенос состояния), тесты ядра остаются
как есть и служат страховкой.

## P3 — UX/UI redesign

Status header на Export, offline-баннер, перестройка Settings по §5 ТЗ, экран Units и Notifications
(реализовать либо убрать), карта экранов из `08_FULL_UX_AUDIT.md`.

## P4 — дополнительные функции

App Intents (Shortcuts), Sync to Mac, категории Activity/Body/Nutrition, фильтрация Recent,
выбор категорий в Manual, прогресс-бар.

## Оценка объёма

| Этап | Работа | Оценка |
|---|---|---|
| P0 | лог, валидация, Keychain-результат | 1–2 дня |
| P1 | Runtime + наблюдаемость фона | 2–3 дня |
| P2 | AppState/async adapter | 4–6 дней |
| P3 | UX-редизайн Settings + баннеры | 4–5 дней |
| P4 | функции | 5–8 дней |
| **Итого 2.0** | | **16–24 рабочих дня**, без учёта device-проверок (требуют подписи) |

## Что сохранить обязательно

Core (61 тест), форматы хранения, wire-контракт, страж бандла и страж снимков с мутационными замками,
P1-гейт проверки профиля. Это единственное, что сейчас реально доказано.
