# 07 — Settings UX review

Проверка каждого пункта на «работает / фиктивно / отсутствует»:

| Раздел | Что видит пользователь | Что происходит на деле | Вердикт |
|---|---|---|---|
| Collection → Automatic collection | тумблер | значение пишется в `UserDefaults` и **не читается никем** | **фиктивный** (CONFIRMED) |
| Permissions | «requested (read status not observable)» + кнопки | честно: iOS не даёт отличить отказ от пустоты | работает, честно |
| Server → Endpoint | поле + Save | мусор молча заменяется production-адресом | **опасно** |
| Server → Token | SecureField + Save | ошибка записи в Keychain не видна | частично |
| Server → Test connection | кнопка | реальный `GET /v1/health`, статус сохраняется в snapshot | работает |
| Sync → очередь/ошибки | счётчики | из `CollectorStatus`, честные | работает |
| Units | экран-заглушка с планом | не реализовано | честно помечено |
| Notifications | экран-заглушка | не реализовано | честно помечено |
| Advanced | все поля + Copy diagnostics | реальные значения, без секретов | работает |
| About | версия, bundle, описание | реальные значения | работает |

## Главный UX-дефект

Пользователь не может ответить на вопрос «работает ли автоматический сбор», потому что:
(a) тумблер декоративен; (b) статус фоновой доставки нигде не показывается (значение
`enableBackgroundDelivery` игнорируется); (c) «последняя синхронизация» обновляется только после
ручного запуска. Три причины складываются в один и тот же ответ «не понятно».

## Предлагаемая структура (по ТЗ §5)

`Collection` (тумблер + состояние фона + типы) · `Permissions` (как сейчас) · `Server` (endpoint с
валидацией, токен с результатом записи, test connection, последний результат) · `Sync` (последняя
попытка/успех, очередь, dead-letter, retry, manual) · `Units` (после реализации) · `Notifications`
(после реализации) · `Advanced` (диагностика, экспорт, версия, состояние компонентов).

Правило: ни одного переключателя, который не влияет на поведение.

## Что нельзя чинить только UI

Тумблер и статус фона требуют правок Runtime (`start()` обязан читать настройку; результат
`enableBackgroundDelivery` обязан попадать в состояние). Это P1 миграции, не косметика.
