# 06 — Network and security review

## Сеть

| Пункт | Факт | Оценка |
|---|---|---|
| Транспорт | `URLSession.shared.dataTask` + `DispatchSemaphore(45 c)` (`Runtime.swift:257-280`) | блокирует вызывающий поток; отмены нет |
| Таймаут | 45 с на батч; в ретрай-политике — свой | приемлемо, но грубо |
| HTTP-коды | `MeasurementClient.decode` классифицирует 2xx/4xx/5xx | корректно, покрыто тестами |
| Malformed ACK | 200 без `accepted` → unconfirmed | корректно |
| TLS | системный, пиннинга нет | приемлемо для self-hosted |
| Валидация endpoint | **отсутствует**: `URL(string:) ?? prod` | дефект (см. ниже) |

## Дефекты безопасности (CONFIRMED)

1. **Молчаливый fallback на production.** `Runtime.swift:43`: неверный адрес в настройках → запросы
   уходят на `https://hermes00.duckdns.org:1118`. Пользователь, опечатавшись, отправляет медицинские
   данные не туда и не узнаёт об этом. Это худший класс дефекта в этом приложении.
2. **Keychain-ошибки проглатываются.** `AppSettings.swift:33-34` — `try?`; UI показывает «stored in
   Keychain» по непустой строке, а не по успешной записи.
3. **Токен в памяти UI.** `ServerView` держит `@State private var token` и очищает его только после
   нажатия Save; при уходе с экрана строка остаётся до пересоздания View.

## Что сделано правильно

- Токен не в бандле: читается из Keychain, в `Info.plist` отсутствует (проверено выгрузкой из IPA).
- `kSecAttrAccessibleAfterFirstUnlock` — разумный выбор для фоновой работы.
- Диагностика не содержит ни токена, ни значений измерений (`Runtime.diagnosticsText`): только счётчики,
  время, хост и `token_configured: Bool`.
- Логи не пишут значения измерений.
- Новый серверный маршрут fail-closed: без токена отвечает `503`, а не пускает всех (старый мост
  наоборот — открыт; это зафиксировано ранее).

## Рекомендации

- Валидировать URL при сохранении: схема https, наличие хоста, отказ сохранять при ошибке, никаких
  fallback-значений в рантайме (пустой адрес = «не настроено», и синхронизация не стартует).
- Возвращать `Result` из записи токена и показывать ошибку.
- Добавить отмену запроса (`Task.cancel`) и убрать семафор в пользу `async/await`.
